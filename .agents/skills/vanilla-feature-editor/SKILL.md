# 《Feature》文稿编辑

在香草图书馆仓库中，将投稿整理为可以交付审阅或发布的 VitePress 页面。保留作者原意、署名、代码语义、来源和适用版本，以现有页面和组件实现为准。

## 确认本次交付

- 区分单篇整理、整期编排和整期发布。只要求文稿整理时，完成稿件与必要资源，不提前将站点“最新一期”切换到未完成的新刊。
- 从用户材料和仓库确定期号 `YYYYMM`、栏目、作者及素材。投稿已编号时，保留编号，并按编号的数值顺序编排目录和侧栏，不重新排序或重新编号。不要仅凭系统日期生成下一期，也不要将下面的历史参考期号当成固定最新期。
- 先查看 `git status --short`，保留用户已有修改。已有当期目录、稿件或编排时，在原处继续，不重编号、不重新搭一套结构。
- 未确定的作者、资源、封面、版本和评论讨论号，记录为待补信息；不编造，也不在正式页面中留下失效的示例链接。

## 先读哪些文件

以下路径均相对于仓库根目录，skill 自身的相对链接除外。

1. 阅读 `feature/_格式指导.md`，必要时查阅 `feature/_条款.md`。根目录 `CONTRIBUTING.md` 的主题是香草前置馆，不能替代《Feature》的约定。
2. 查看最近一期 `feature/index/YYYYMM.md` 及同一期相近类型的文章、`ifc/content.md`、`spotlight/content.md`。初始参考可用 `202610` 与 `202609`；执行时重新确认实际最近一期。
3. 涉及排版、目录或资源时，阅读 [仓库与组件约定](references/repository-conventions.md)；新建页面时，按需使用 [页面模板](references/page-templates.md)。
4. 对不确定的属性查 `.vitepress/vue/` 中对应组件及 `.vitepress/theme/index.ts` 的全局注册。往期存在简写或疏漏，不能将所有历史写法都视为规范。

## 整理稿件

1. 为每篇稿件建立稳定映射：源稿 → 标题 → 栏目 → 作者 → 目标目录 → 摘要 → 图片/附件 → 待确认事项。少量文章可在工作记录或回复中维护，不必新增站点页面。
2. 接收的投稿主 Markdown 无论原文件名为何，均归档为 `feature/archive/YYYYMM/<原编号>/content.md`。不要另存一份原名 Markdown 而生成重复页面；已有附篇或引用文件按实际用途保留。
3. 标题优先取文章内部大标题，找不到才依次查投稿信息、文件名等材料。将该标题写入 frontmatter 和 `FeatureHead` / `FeaturedHead`，移除原大标题以免重复。
4. 投稿正文原样保留，只删除可能附带的独立作者信息，并转换大标题。不要润色、重排章节、修正标点、改写代码、补充摘要或替换原链接；正文中的引用署名、致谢、版本声明和 AI 使用说明均保留。疑似错误单独反馈。确实阻止编译的原稿标记问题，先说明具体位置；只有用户授权相应修正后才调整。
5. 文内配图可直接放在编号目录下，沿用原稿使用的图片子目录和文件名，使正文图片引用无需改动。文章封面、示例数据包等附加文件放在当期 `_asset/`（单数）下，并按相同相对路径备份到 `public/feature/archive/YYYYMM/_asset/`。可用 `_asset/<编号>/` 避免重名；历史 `_assets/` 不迁移。
   正文中的远程图片引用必须转存到对应编号目录（例如 `<编号>/images/`），再将 Markdown 或 HTML 图片路径改为本地相对路径；扫描整期稿件，不能遗漏其他文章的远程图片。只处理图片资源，正文中的普通外部链接、项目仓库和参考文献链接保持原样。下载后核对文件确为图片且页面引用路径存在。
6. 示例数据包必须通过页头组件的 `resourceLink` 引用，使用能访问到 public 镜像的相对路径；有文章对应项目的外部链接（仓库、博客原文、发布下载页）时也可填入此属性。没有本地示例包时优先选最相关的项目入口；不要把投稿原始压缩包当成示例包。
7. 先按作者注册文件名、JSON 内 `name` 和已知社媒账号查找既有作者，复用对应注册键；显示名和文件名可能不同。未注册时，按投稿目录中的资料自动创建 `public/authors/<注册键>.json`，默认从该作者提供的 B 站账号提取当前头像，下载到 `public/_authors/` 后再引用，不能仅热链头像或挪用他人资料。缺少可判定的署名/账号时仅询问缺失项，不猜作者。
8. 使用现有全局组件；只在确有本地导入、响应式状态等需求时增加 `<script setup>`。不要为文章排版修改全局主题、依赖或组件 API。原稿自带摘要保持原样，目录卡片另填 `abstract`；缺少摘要时只在目录提炼摘要，不改投稿正文。

## 整期编排与发布

当任务包含整期目录或上线时，按真实选稿同步以下入口。目录、侧栏的文章集合和栏目顺序应一致；栏目数量和文章数量不固定。

- `feature/index/YYYYMM.md`：`JournalHead`、栏目与 `IndexCompatible` 卡片。index 页封面使用仓库已有占位图，必要时复制到当期 `_asset/` 并镜像到 public；不要自行设计封面或借用旧刊正式封面。编辑名单未提供时传空数组，避免组件默认的虚构名字。
- `.vitepress/sidebar_featureYYYY.ts`：新增/更新 `sidebar_YYYYMM`，包括目录、相邻期、封二和各栏目文章。
- 编辑整期时，始终预留 `ifc/content.md`（封二）与 `spotlight/content.md`（香草快讯），并接入目录及当期侧栏。尚未收稿时明确标注“编辑中”，只留栏目骨架，不编造正文、署名、版本或摘要；Spotlight 署名未定时先用普通大标题，收到稿件后再转为 `SpotlightHead`。
- 目录和封二均预留 `<ClientOnly>` 包裹的 `GiscusComment`，使用 `useData().isDark` 切换主题，同一期可共用一个 Discussion。编号未定时保留 `discussionNumber = ''`，用 `v-if="discussionNumber"` 禁止挂载；不能借用上期编号，也不能因未取得编号就省略评论组件。确认编号后同步填写这两页。Spotlight 不设置评论区，也不添加仅用于评论的脚本、主题状态或讨论编号。
- 需要新建 Discussion 时，先检索 `CR-019/datapack-index` 的现有讨论，避免重复；使用已验证的仓库、分类与编号。用户已允许按需建立 Discussion 时可在现有授权范围内创建；缺少 GitHub 登录或所需权限时，告知所需授权，先完成本地预留，不泄露或索取令牌明文。
- `.vitepress/config.mts`：导入该期侧栏，并在通用 `/feature/` 匹配之前注册 `/feature/archive/YYYYMM`。跨年时按既有模式建立新的年度侧栏文件。
- 上一期侧栏：当新刊确实可访问时补“下一刊”，新刊补“上一刊”；不要预先指向不存在的未来期。
- `feature/_index.md` 与 `.vitepress/sidebar_feature.ts`：发布时同步“最新”和往期顺序，保留旧刊入口且避免重复。
- 根目录 `index.md`：发布时更新首页《Feature》卡片的期号链接。
- `.vitepress/sidebar.ts`：发布时同步主站侧栏中的最新一期与最近往期，保持与 Feature 总索引一致。
- `public/authors/` 与 `public/_authors/`：按上述查重、注册和 B 站头像本地保存规则补齐本次作者；多作者同时体现在正文页头与目录卡片。
- 英文页面只在用户要求时同步；先检查 `.vitepress/sidebar_en.ts` 的显式年度导入和期号映射，不能假定会自动覆盖新增期刊。若使用翻译脚本，限定到目标文件，避免全仓翻译。

封二的题目、出题人、上期参考答案及新闻稿均须来自当期材料。不要把上一期正文、编辑名单、快照版本或 Giscus `term` 原样当作新一期内容。

## 验证与交付

- 检查 frontmatter、Vue 标签、数组绑定、代码围栏、折叠块及脚注闭合；确认标题、署名、摘要在正文和目录中的对应关系。
- 检查本地图片、附件、文章链接、组件导入与文件名大小写。Vue 属性中的路径同样要查；仓库启用了 `ignoreDeadLinks: true`，构建成功不代表链接正确。
- 检查作者 JSON 可解析且文件名与署名相符，多作者页头及卡片均完整显示署名。
- 将归档后的正文与原稿对照，只允许大标题替换、独立作者信息删除及用户另行授权的修正；核对编号顺序不变，`_asset/` 文件与 public 镜像校验和一致，示例包的 `resourceLink` 指向实际文件。
- 页面变更后，从根目录运行 `pnpm docs:build`；实际脚本还会生成 wheel 静态索引并优化输出图片。完成后复查 `git status --short`，不要将无关生成物混入交付。涉及底层渲染或组件行为才补跑相应测试。
- 条件允许时用 `pnpm docs:dev` 或 `pnpm docs:preview` 检查桌面/窄屏和明暗主题，重点看页头、头图、多作者、代码、NBT 树与公式。`docs:preview` 应在完整构建（含图片优化）结束后启动；若启动过早，优化后重启，以免预览服务缓存旧文件长度。只报告实际执行过的验证；构建失败时指出具体原因，不通过关闭校验掩盖问题。
- 交付时简述稿件位置、完成范围、验证结果和仍待补的编辑信息。除非用户要求，不自动提交、推送或发布。

## 本 skill 的存放边界

本 skill 及其说明留在 `.agents/skills/vanilla-feature-editor/`，供仓库内复用。不要将它们复制到 `feature/`、`public/` 或导航中。VitePress 是否收录隐藏目录应以当前安装版本的实际页面发现结果为准；升级后若改变此行为，再精确设置排除规则，不为本 skill 重排业务目录。
