# "Feature" Submission Format Guide

<ColorLine :height="4"/>

This article aims to provide specifications and suggestions for submission formats for creators who intend to submit to "Feature", and lists the special formats supported by this site to facilitate authors' use.

## Format specifications for submissions

### Text format

"Feature" accepts submissions in Markdown format.
If you are not familiar with Markdown, you can quickly get started with the following tutorial:

- &lt;https://commonmark.org/help/&gt;
- &lt;https://www.markdown.cn/docs/tutorial-basics/basic-syntax&gt;

Of course, you can also use the following online editor experience:

- &lt;https://ld246.com/guide/markdown&gt;
- &lt;https://milkdown.dev/playground&gt;

### Article structure

"Feature" has no strict requirements on the topic selection and writing format of submitted articles, as long as they are related to mcvanilla development. When adopting, the editor may conduct certain discussions and modifications with the author based on the topic of the article.

We recommend including an abstract of the article at the beginning of the article. It will be displayed on the index page and at the beginning of the article, and is an effective tool for readers to briefly understand the central idea of ​​the article.

Regarding the pictures or file references involved in the article, if you need to quote them locally, please put the corresponding pictures and files in the same folder as the document, and package and send them when submitting.

### Submission template

We recommend that authors package the article, pictures used in the article, and some other information into a .zip compressed package and send it to &lt;1703467028@qq.com>;

The compressed package can contain an additional folder, in which you can place the header image, the author's social media account information, other descriptions about the article, etc.; when included, the contents will be moved elsewhere.

Below is a sample template we created for contributors to refer to.

[Example template.zip](/feature/example.zip)

## Appendix: Common special format reference

Vitepress and this site have made some extensions beyond the standard markdown syntax. You can freely use these new syntaxes to optimize the layout of your documents.  

In addition, you can also upload your manuscript to our [Preview Window](/en/preview/) to preview how it will appear in the library:

### Custom comment block

Vitepress has added some new block-level elements that you can use to make comments:

```markdown
::: tip tip title
Here is the tip content.
:::

::: warning warning title
Here is the warning content.
:::

::: danger error title
Here is the error content.
:::
```
They will render as shown below:

::: tip tip title
Here's what the prompt says.
:::

::: warning warning title
Here's what the warning says.
:::

:::danger error title
Here is the wrong content.
:::

If you use Typora to write Markdown, maybe you are more familiar with Github-style prompt boxes. Of course, Vitepress also supports this. As shown below:

```markdown
> [!TIP]Tip

> [!WARNING]Warning

> [!DANGER]Danger
```
### Folding block

In addition, vitepress adds a folding block element, which you can use in the following ways:

```markdown
::: details folding block
Here is the collapsed content.
:::
```
The rendering effect is as follows:

::: details folding block
Here is the collapsed content.
:::

### Formula
markdown supports two types of formulas:

- Inline formulas: use a single`$`wrap formula block;
- Formulas on one line: start a new paragraph and use two`$$`Wrap formula blocks.

After testing, inline formulas may not support the rendering of more complex formulas. If necessary, try to use a formula block that occupies one line.

### Sidebar
By default, vitepress supports automatically integrating level 2-6 titles into the right sidebar as index navigation.
First-level titles **will not be automatically integrated by default**. Authors need to pay attention when submitting their manuscripts and try to minimize the use of first-level titles.

#### Folding block
We also support the use of folded blocks in NBT trees, and have registered a blue background style similar to wiki. Specific performance can be seen in the above example.
The usage of folding blocks is similar to the usage of general HTML tags:
- Use HTMLtag`&lt;detail&gt;` `&lt;/detail&gt;`wrap folded blocks;
- in`&lt;detail&gt;`You can follow later`<summary>` `</summary>`Package summary description.

However, you need to pay attention to the following points when mixing folding block HTML tags in md documents:
-`&lt;detail&gt;`An **empty line** is required below so that the unsequenced table format of md can be parsed correctly;
-`&lt;detail&gt;`and`&lt;/detail&gt;`Need to be written in **the same series of indents**;
- The indentation of unordered lists inside a collapsing block must be no less than the indentation of the collapsing block itself.

The following is the **correct** way of writing:

```html
    <details><summary>folding block style test</summary>

    -  <node type="compound" name="compound4"/>Put some tags inside.
        -  <node type="any" name="any"/>Put some tags inside.
        -  <node type="compound" name="compound5"/>This is a nested folding block style test.
            <details><summary>Nested folding block style test 1</summary>

             - <node type="any" name="any"/>Put some tags inside.
             - <node type="any" name="any"/>Put some tags inside.
            </details>
            <details><summary>Nested folding block style test 2</summary>

             - <node type="any" name="any"/>Put some tags inside.
            </details>

    </details>
```
The following is **wrong**:

```html
    <details><summary>folding block style test</summary>

    -  <node type="compound" name="compound4"/>Put some tags inside.
        -  <node type="any" name="any"/>Put some tags inside.
        -  <node type="compound" name="compound5"/>This is a nested folding block style test.
            <details><summary>Nested folding block style test 1</summary>

          - <node type="any" name="any"/>Put some tags inside.
          - <node type="any" name="any"/>Put some tags inside.
            </details>
            <details><summary>Nested folding block style test 2</summary>
            - <node type="any" name="any"/>Put some tags inside.
            </details>

</details>
```
#### Other tips

- If a key can accept values of multiple types, you can arrange multiple on the same line`node`components, but only fill in the last component`name`，`required`and other parameters.
- Since the rendering of the nbt tree relies on an unordered list, and in markdown's default format, breaking the unordered list within one line will not affect the rendering of the entire list. You can add some conditional descriptions in another line, etc.
  - Of course, it will appear as the same line on the render. You still need to use`<br>`to change the line.
  - You can also use htmltag directly`<ul>` `<li>`Make more custom writing.
- We currently do not support the use of folding blocks and common tags within the tree. Support may be provided in the future, so stay tuned.
